# ADR 0004 — Drizzle ORM + PostgreSQL

**Status:** Accepted · **Date:** 2026-06-16

## Context
We need a type-safe data layer with reliable migrations for a relational domain (customers, subscriptions, line items, invoices, audit logs) with strong tenant constraints and `jsonb` fields. The Scope of Work already chose Drizzle + PostgreSQL, and it remains the best fit, so this ADR confirms rather than changes the decision.

## Options considered
1. **Prisma** — mature, great DX, but a heavier runtime and historically less direct SQL control; RLS integration is more awkward.
2. **Drizzle ORM** — thin, SQL-first, fully typed, first-class migrations (drizzle-kit), easy raw SQL for RLS and analytics.
3. **Raw SQL / query builder only** — maximal control, least safety and ergonomics.

## Decision
Use **Drizzle ORM** with **PostgreSQL 16**. Schema in `lib/db/schema.ts`; migrations generated by drizzle-kit and committed; money as integer cents; `jsonb` for line items, features, addresses, and audit metadata. A post-migration step revokes UPDATE/DELETE on `audit_logs` and enables RLS (see ADR 0005).

## Consequences
**Positive:** end-to-end types from DB to UI; transparent SQL for performance and RLS; lightweight runtime suited to serverless.
**Negative:** smaller ecosystem than Prisma; some advanced relations are more manual. Acceptable given the control RLS and analytics require.

## Revisit if
The team strongly prefers Prisma's DX and RLS/analytics needs can be met through it.
